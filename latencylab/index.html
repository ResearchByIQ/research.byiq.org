The problem

General cores hide the shape of the work.

A general-purpose processor runs every algorithm by streaming it through the same fixed pipeline. The structure of the problem — which values depend on which, what can run at once — is flattened into an instruction sequence, and the latency you get is the latency of the ISA, not of the computation.

For the workloads where latency is the product, that flattening is the ceiling. The dependency graph is known; it is simply not allowed to shape the hardware.

The approach

Let the graph become the layout.

01

Decompose to dataflow

A high-level algorithm is decomposed into its dataflow graph — the operations and the dependencies between them — as the design input, rather than compiled down to instructions for a fixed core.

02

Floorplan from the flow

That graph is mapped directly onto silicon, so independent work runs in parallel by construction and the critical path of the chip is the critical path of the algorithm — the target is latency bounded by the problem itself.

What's next

From simulation to fabric.

The near-term goal is a reference algorithm carried end to end — decomposed, mapped and validated on an FPGA — with the latency measured against a conventional core on the same workload.
