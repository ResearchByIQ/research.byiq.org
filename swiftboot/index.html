The problem

Cold boot is the tax on elasticity.

Scaling to zero only pays off if scaling back up is instant. A general-purpose Linux image spends most of a cold boot probing hardware and starting services the workload will never use, so operators keep machines warm to hide the latency — and pay for idle capacity to do it.

The image is general because it does not know what it will run. When the application is known at build time, almost everything the stock kernel does on the way up is wasted work.

The approach

Build the image around the app.

01

Minimal kernel per workload

The image is composed for one OCI application: only the drivers, subsystems and init that workload needs, targeting a cold boot in the tens of milliseconds on a cloud hypervisor.

02

The application, included

The OCI container ships inside the bootable image rather than being pulled and started afterwards, so first request is served the moment the guest is up — no separate runtime to schedule.
